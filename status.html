Read this first

1197 and 1198 shipped a crash to production Fixed in 1200

Change the app colour, tap Home, crash — every time, fully reproducible. ScoreFrameActivity.onResume called recreate() on an already-visible screen, which takes Android's local relaunch path; AppCompat rebuilds its sub-decor wrong there and the next setContentView hits a null content frame.

A system light/dark switch never crashed — that's a config-change relaunch, a different path. That contrast is what identified it. 1200 restarts the screen cleanly instead of using recreate().

An earlier fix (1199) did not work. It was shipped on a theory that hadn't been reproduced. Worth remembering next time: reproduce first.

Sharing told you the wrong thing, twice

A refusal at your shared-team limit came back as "Check your connection". It now names every team the server counted. And a team that had dropped out of your list was still shared and still counting — invisible in the app, unfixable from it. Counted teams missing from your list are now restored so you can act on them.

Archived teams, un-share, and stuck hubs

An archived team can be re-shared at your cap (archived teams hold no slot — reviving is where the limit belongs). Un-sharing now parks the code, so re-sharing keeps the same link. A team that claimed a code with no lookup row showed as shared while the web 404'd — both apps now verify before showing it as shared.

Message one user in the app

Admin app → User Lookup → their record → Send in-app message. Delivers to a private per-user inbox, not email and not a broadcast, so it can't leak to anyone else. Push is attempted too and the result is reported honestly. Needs Android 1200 / iOS 622 on the recipient's phone.

What the numbers actually say

"10 new users" was 2

7 were automated signups matching name.NNNNN@gmail.com — they authenticate against Firebase Auth directly, never open the app, and write nothing. 3 were anonymous web sessions from the scoring page, which were never signups. The digest read a collection nothing had written in months; it now reads Auth itself and labels every account. Over 30 days: 39 accounts, 4 recorded a game.

59% of push tokens are dead — and that's churn, not a bug

41 of 99 are deliverable. Dead rate tracks time since last app open (33% within 7 days → 68% past 90), which is the shape of uninstalls. The token refresh path was already correct. A failed send now stamps uninstalledAt so it reads as a retention metric. This is why the email matters: it reaches people the app can't.
